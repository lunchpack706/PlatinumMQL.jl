# 元のリポジトリ（ryuzakilime/platinum-mql）を動かすために補った点

対象: `platinum_transpiler.jl`（v3.2）と `README.md`（2026-04-27 時点の main ブランチ）。
本リポジトリ（PlatinumMQL.jl）を作る前に読み、MT5 で運用する際に補う必要がある点を整理したもの。
「どこを補ったか」「どう実装したか」を対応づけています。

確認方法: #1 は Julia 1.13 で実際に ParseError になることをテストで確認しています（`test/runtests.jl`）。
#2〜#13 はソースコードを読んで判断したもので、上流のコードを実行して確かめたものではありません。

## DLL を使わない構成にした理由

MT5 の EA から Julia のコードを呼ぶには、Julia ランタイムを含む共有ライブラリを Windows 向けにビルドし、
EA の「DLL の使用を許可」を有効にする必要があります。配布先の環境ごとに Julia の DLL 群を置くことになり、
VPS での運用や配布の手間が大きくなります。

一方、Black-Scholes の価格や Greeks は数十行の数式なので、MQL5 で書けば DLL は要りません。
そこで本リポジトリでは次の分担にしました。

- **EA（MQL5）**: 解析解・注文・ポジション管理。生成された .mq5 だけで動く
- **Julia**: モンテカルロ・パラメータ探索などの重い計算。結果を `input` パラメータとして EA に渡す

MQL5 側の正規分布の累積分布は近似式（Abramowitz & Stegun 26.2.17）で実装しています。
同じ式を Julia にも実装し（`normcdf_as`）、厳密な値との差が −8〜8 の範囲で 1e-7 未満であることをテストで確認しています。
バックテストもこの近似式で計算するので、EA と Julia の売買判断が一致します。

DLL 連携が必要な場合（ティックごとに MC を回すなど）は、文字列ではなく整数の種別コードで受け渡す、
初期化（`jl_init`）を `OnInit` で 1 回だけ行う、などの設計で対応できます。
